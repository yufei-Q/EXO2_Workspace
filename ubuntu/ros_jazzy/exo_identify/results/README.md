# Identification Results

This directory contains reproducible data and artifacts generated by the
`exo_identify` package. The source code remains in the package-level
`scripts/`, `config/`, `launch/`, and `urdf/` directories.

## Layout

```text
results/
├── seven_dof/                  # Current seven-DOF outputs
│   ├── excitation/             # Designed excitation trajectories and reports
│   ├── simulation_data/        # MuJoCo forward-simulation CSV data (*_sim files)
│   ├── simulation_model/       # Generated MJCF model and mesh assets
│   ├── model_visualization/    # Preview MJCF/PNG files (PNG is opt-in)
│   ├── dynamics_identification/# Identified parameters; `_sim` marks simulation
│   ├── compensation_validation/# Independent gravity/friction validation
│   ├── neural_identification/  # Optional NumPy neural-model outputs
│   └── hardware_experiments/   # Raw and processed real-hardware recordings
└── two_dof/                    # Historical two-DOF results; not valid for seven DOF
```

The default output locations are inside this directory so that experiment
artifacts can be reviewed and versioned together with the package. Pass an
explicit `--output-dir` or ROS parameter when a run should be stored elsewhere.

Physical motor-to-joint calibration is kept separately in
`../config/hardware_mapping.yaml` and is shared by both real-hardware nodes.

The shared trajectory in `seven_dof/excitation/` is used by both simulation and
hardware. Simulation collection files use the `_sim` suffix; hardware runs are
stored separately under `hardware_experiments/` and do not reuse simulation
files.

The complete simulation keeps each stage's artifacts in its own directory:
`simulation_data/` contains forward-simulation CSV files, `simulation_model/`
contains the generated MJCF and mesh assets, `dynamics_identification/` contains
identified parameters and the exported gravity formula, and
`compensation_validation/` contains the independent deployment precheck. All
simulation artifacts use the `_sim` suffix. Model-preview outputs are kept in
`model_visualization/`; a PNG is generated only when `mujoco_model.py --preview`
is requested. The checked-in MuJoCo models use relative mesh paths so they can be
loaded after cloning the repository on another machine.

The CSV files in `simulation_data/` are produced by a live MuJoCo forward
simulation. A position/velocity virtual servo applies the command, `mj_step`
advances the model, and the collector records the resulting joint state and
`qfrc_actuator`; configurable control, external-torque, and sensor noise is
stored in `simulation_metadata_sim.json`.
